# Free Pilot Deployment Runbook

## Service accounts

Create the following accounts without sharing any credentials in chat:

1. **Google AI Studio:** create a new server-side Gemini key after revoking the key previously shared in chat.
2. **Qdrant Cloud:** create a Free cluster; record its HTTPS URL and an API key.
3. **Hosted PostgreSQL:** create a Free PostgreSQL project. The backend owns the schema and migrations; the provider supplies infrastructure only.
4. **Render:** connect the private GitHub repository and deploy from `infra/render.yaml`. One web service is all this needs — it runs an embedded worker in its own process.
5. **Vercel:** connect the same repository and select the `frontend` directory as its root (Claude's Next.js app).
6. **Optional:** create Tavily and Langfuse accounts only when web search and tracing are enabled.

### Not required

- **No SMTP provider.** Signing up and signing in never send email. The only flow that needs it is self-service password reset, which stays hidden and unavailable until one is configured. Until then, an account that loses its password needs an administrator.
- **No Redis, and no separate worker.** Runs and documents are durable rows either way, and a restart still recovers work that was in flight. Adding them separates execution from the API, which matters once the web service needs more than one instance — the commented blocks in `infra/render.yaml` do it, and no application code changes.

If you do add the worker later, it and the web service must always deploy from
the same commit. They share a schema, and a worker running older code against a
newer database is the failure that arrangement is prone to.

## Render environment variables

Add these in Render's dashboard as secrets. Never put them in `render.yaml` or Git:

```text
DATABASE_URL
GEMINI_API_KEY
QDRANT_URL
QDRANT_API_KEY
OBJECT_STORAGE_ENDPOINT
OBJECT_STORAGE_REGION
OBJECT_STORAGE_ACCESS_KEY_ID
OBJECT_STORAGE_SECRET_ACCESS_KEY
```

`ALLOWED_ORIGINS` and `PUBLIC_APP_URL` are already set in the blueprint to
`https://multi-agent-ai-analyst-psi.vercel.app`. Both are validated at startup,
and both are the **browser app's** origin — not the API's. `PUBLIC_APP_URL` is
what password-reset links are built from, so pointing it at the API produces
links that go nowhere.

`JWT_SECRET_KEY` is generated by Render. Leave `REDIS_URL` and the `SMTP_*`
variables unset unless you are deliberately adding those capabilities.

Set `APP_ENV=production`, `EMAIL_SENDER=console`, `ENABLE_WEB_SEARCH=false`, and `ENABLE_CODE_EXECUTION=false` for the first release.
Do not set `LITELLM_BASE_URL`; production calls Gemini directly.

### Optional Langfuse tracing

To trace a pilot, create a Langfuse project and add these server-only Render
secrets. Then set `ENABLE_LANGFUSE_TRACING=true`; otherwise leave it `false`.

```text
LANGFUSE_PUBLIC_KEY
LANGFUSE_SECRET_KEY
LANGFUSE_BASE_URL            # EU default: https://cloud.langfuse.com
```

Traces intentionally contain workflow names, safe metadata, and provider token
usage—not questions, uploaded document text, prompts, answers, SQL, or secrets.
Run one development-demo question and verify the trace contains the supervisor,
selected tool/agent, answer generation, critic, and model token counts before
enabling it for any pilot traffic.

## Vercel environment variables (frontend)

Add these in the Vercel project → Settings → Environment Variables (Production).
They are all public (`NEXT_PUBLIC_*`); there are no frontend secrets:

```text
NEXT_PUBLIC_API_BASE_URL   # the deployed Render backend URL
NEXT_PUBLIC_API_V1_PREFIX  # /v1
NEXT_PUBLIC_APP_ENV        # production
NEXT_PUBLIC_ENABLE_PASSWORD_RESET  # false unless SMTP is configured
```

After the frontend URL is known, add it to the backend's `ALLOWED_ORIGINS` and
remove `localhost` from the production value.

## First deployment gate

Do not expose the pilot publicly until all of these are true:

- `GET /healthz` is successful from the Render URL.
- `alembic upgrade head` completes against the application database.
- `GET /readyz` reports every required integration as configured and reachable.
  `queue` reports ready without Redis — the embedded worker has no socket to
  fail on.
- The service log shows `embedded_worker_started` (or `worker_started` on a
  separate worker service, if you added one).
- An unauthenticated `POST /v1/runs` returns `401`, not `404` or `500`.
- One real account completes the whole loop: sign up, land in the workspace,
  upload a document, watch it reach `ready`, ask a question, and get a cited
  answer.
- A second account in a different workspace cannot see the first one's
  documents or runs.
- The backend is restarted mid-run and the run still reaches a terminal state.
- The database uses a non-owner, application-specific role in production.
- Qdrant and database credentials are server-only.
- The deployed `ALLOWED_ORIGINS` contains the Vercel frontend URL only.
- Gitleaks passes against the complete Git history.
- No API key or real env file appears in
  `git log --all -- backend/.env.development backend/.env.production`.

Free infrastructure is appropriate for a portfolio/pilot deployment, but not an uptime or backup guarantee. Upgrade managed services before storing sensitive data or promising availability.
